# Repository map

English · [Français](REPO_MAP_FR.md)

Where things live in Better Mod Manager (BMM), how the pieces connect, and where to start for
common tasks. For working rules (gates, i18n, encoding, security) see [AGENTS.md](AGENTS.md) and
[CONTRIBUTING.md](CONTRIBUTING.md).

---

## Top level

| Path | What it is |
|---|---|
| `frontend/` | The app's UI (Tauri `frontendDist`): `index.html`, TypeScript sources, CSS, translations, bundled assets and docs. |
| `src-tauri/` | The Rust core: Tauri commands, the local HTTP API, the MCP server and CLI, the resource governor, Tauri config. |
| `scripts/` | Node gates (`check-*.mjs`), generators (`gen-*.mjs`), maps, docs sync, release helpers. |
| `tests/` | Node unit tests (`*.test.mjs`, run by `npm test`) and `fixtures/`. |
| `Update/` | Changelogs per version, `Documentation/` (technical references, EN + FR), `Guides/`, and older release notes (`Old/`, `Updates/`). |
| `BMM Docs/` | Git submodule: the documentation site (mkdocs, EN + FR). Its pages are copied into the app by `scripts/sync-docs.mjs`. |
| `BetterInstaller/` | Git submodule: the installer and updater that ships BMM (`examples/bmm/` holds BMM's installer config and build scripts). |
| `BCW/` | Git submodule: BetterCommunity Web (BCWEB, the website, API and Discord bot). BMM talks to it over HTTP; nothing here builds it. |
| `.github/` | CI workflows, the security gate, Semgrep rules, README screenshots. |
| `benchmarks/` | Criterion, JS and hyperfine benchmarks (see `benchmarks/README.md`). |
| `dev-pages/` | Standalone development pages, never shipped (see `dev-pages/README.md`). |
| `dist-assets/` | `bmms-vocabulary.json`, generated by `scripts/gen-bmms-reference.mjs`. |
| `video-out/` | Loader and exit animation videos rendered by `scripts/record-*.mjs`. |
| `app.cfg` | Build flags read at startup (documented in `APP_CFG.md`). |
| `laya-model.lock.json` | Pins of the offline AI model pack (checked by `scripts/check-laya-pins.mjs`). |
| `progress.json` | Roadmap progress read by the website (explained in `PROGRESS_TRACKER.md`). |
| `ENDPOINTS.md` | Every URL BMM talks to and what breaks if it fails. |
| `RELEASE.md` | How a release is built, signed and published. |
| `PRIVACY.md`, `TOS.md` (+ `_FR`) | Privacy policy and terms shown to users. |

Not in git (ignored): `node_modules/`, `dist/`, `src-tauri/target/`, `src-tauri/gen/`, `Release/`
(installer output), `.Assets/` (owner's plans and assets), `.claude/` (agent settings and worktrees),
`tmp/` (scratch, also the default work folder of `scripts/laya/build_pack.py`).

## frontend/

| Path | What it is |
|---|---|
| `src/core/` | Shared services: `state.ts`, `api.ts` (Tauri invoke wrappers), `i18n.ts`, `commands.ts` (Ctrl+K palette registry), `deep_link_manager.ts`, `consent.ts`, `links-config.ts`, BetterCommunity client (`bc-*.ts`). |
| `src/features/` | One folder per feature: `ai`, `apps`, `bench`, `catalogs`, `community`, `debug`, `dev`, `feedback`, `mapper`, `misc`, `mods`, `plugins`, `profiles`, `repo`, `settings` (also the scheduler), `themes`, `tools`. |
| `src/ui/` | App shell and shared UI: `app.ts` (boot), modals, `modal-shell.ts`, `custom-select.ts`, tutorials, onboarding, titlebar, notifications. |
| `src/docs/` | In-app docs: `docs-hub.ts`, the B.MD renderers (`md-lite.ts`, `md-safe.ts`, `md-hydrate.ts`), diagrams, replays. |
| `src/types/` | Shared types (`models.ts`) and Tauri typings. |
| `js/` | Compiled output of `src/` (`tsc --project frontend`). `js/lib/` holds vendored libraries (DOMPurify and others), the rest is generated. |
| `css/` | Stylesheets; `tokens.css` holds the theme tokens. |
| `Lang/` | `en.json`, `fr.json` (must have the same keys) and `template.json` (the translator template). |
| `assets/` | Images, icons, `links.json` (the link registry), vendored code, `docs/` (synced copy of BMM Docs), generated credits. |
| `index.html` | All static markup, including every Settings card (`data-i18n` attributes). |
| `deeplinks.json` | Generated table of `bmm://` routes. |

## src-tauri/

| Path | What it is |
|---|---|
| `src/main.rs` | App entry: plugins, state, and the `invoke_handler` that registers every Tauri command. |
| `src/state.rs` | Persistent app data, including `AppSettings`. |
| `src/commands/` | Tauri commands, one module per area (`mods.rs`, `profile.rs`, `repo*.rs`, `catalog_*.rs`, `scheduler.rs`, `autoupdate.rs`, `consent_ledger.rs`, `ai_*.rs`, ...). `proc.rs` holds the only allowed way to spawn processes. |
| `src/api/mod.rs` | Local HTTP API (warp), bound to `127.0.0.1`, default port 51274 (setting `api_port`), token and per-plugin permissions. |
| `src/mcp/` | MCP server: `server.rs`, `tools/` (tool groups), `state_bridge.rs` (calls the running app through the local API), `actions.gen.json`. |
| `src/extra_tools/mcp_server.rs` | The `bmm-mcp-server` binary (a cargo `[[example]]`): MCP over stdio and the CLI (clap `Commands` enum). Shipped as the sidecar in `binaries/`. |
| `src/governor/` | Resource governor: queues, process priorities, I/O pacing, game mode. Heavy work goes through it. |
| `src/models/` | Data models (mods, profiles, modpacks, repos, catalogs, launch packs). |
| `src/templates/` | Files written out for users: `docker/` (Dockerfiles, compose) and `mini-server/` (standalone repo server). |
| `tests/` | Rust test fixtures (repo and catalog formats, Laya eval sets). |
| `capabilities/` | Tauri permission sets. |
| `tauri.conf.json`, `Cargo.toml` | App config and version. |

## scripts/

- `check-*.mjs`: CI gates. `npm run ci` (in `package.json`) runs them in order, plus `tsc`,
  `npm test` and `sync-docs --check`.
- `gen-*.mjs`, `deeplink-map.mjs`, `dep-graph.mjs`: generators; most have a `--check` mode used by CI.
- `sync-docs.mjs`: copies `BMM Docs/docs` into `frontend/assets/docs`.
- `security-guard.mjs`: blocks code-from-string execution, new inline event handlers and dev pages inside `frontend/`.
- `gen-update-manifest.mjs`, `sign-update-manifest.mjs`, `publish-bcweb-asset.mjs`: release assets.
- `laya/`: Python tooling for the offline AI pack.
- JSON baselines and allowlists used by gates (`governed-allowlist.json`, `dep-graph.baseline.json`, ...).

## .github/

- `workflows/ci.yml`: gate chain (`npm run ci`), `cargo check`/`cargo test`, npm and cargo audit. Runs on `main` and `Tdev`.
- `workflows/security.yml`: gitleaks, Semgrep and the security gate (`.github/scripts/security-gate.mjs`).
- `workflows/release.yml`: builds and publishes a release on a `v*` tag.
- `workflows/resign-manifests.yml`: renews the signed update manifests before they expire.
- `workflows/laya-model.yml`: builds the offline AI model pack.

## How the pieces connect

- **TypeScript to JavaScript**: `frontend/src/**/*.ts` compiles to `frontend/js/**` (`npm run watch`
  in dev, `tsc --project frontend` in build and CI). `index.html` loads the compiled files.
  `check-compiled-fresh.mjs` verifies the committed JS matches the TypeScript.
- **UI to core**: the UI calls Tauri commands (`invoke`). A command is a Rust function in
  `src-tauri/src/commands/` registered in `main.rs`. `check-invoke-names.mjs` checks both sides agree.
- **Local HTTP API**: plugins, custom pages and the CLI/MCP reach the app through `src-tauri/src/api/mod.rs`.
  Reference: `BMM Docs/docs/reference/api.md` and `Update/Documentation/API_Reference_EN.md`.
- **CLI and MCP**: one binary, `bmm-mcp-server`. It works offline on the data folder and, when BMM
  is running, forwards live actions through the local API (`state_bridge.rs`).
- **Docs**: written in `BMM Docs/docs` (`page.md` + `page.fr.md`), published as a site, and copied
  into the app by `sync-docs.mjs` for Help & other. Markdown is rendered with B.MD.
- **Release**: `npm run build` (gates, compile, `tauri build --no-bundle`, update manifest), then
  `npm run build:installer` (BetterInstaller, `BetterInstaller/examples/bmm/`), then signed manifests
  and assets. Details in [RELEASE.md](RELEASE.md).

## Where to start

| Task | Start here |
|---|---|
| Add a setting | Field with a serde default in `AppSettings` (`src-tauri/src/state.rs`); card markup in `frontend/index.html`; logic in `frontend/src/features/settings/settings.ts`; keys in `frontend/Lang/`; mention it in the matching BMM Docs page. |
| Add a Tauri command | Function in a module of `src-tauri/src/commands/`, registered in `generate_handler!` in `src-tauri/src/main.rs`, called from `frontend/src/core/api.ts` or the feature. Spawn processes only via `commands::proc`. |
| Add an API route | `src-tauri/src/api/mod.rs` (with `require_permission`), then the API reference pages (`check-api-docs`, `check-api-perms`). |
| Add an MCP tool or CLI command | `src-tauri/src/mcp/tools/` or the `Commands` enum in `src-tauri/src/extra_tools/mcp_server.rs`, then `BMM Docs/docs/reference/mcp.md` / `cli.md` (`check-mcp-tools`, `check-cli-reference`). |
| Add a translation | Keys in `frontend/Lang/en.json` and `fr.json`, then `node scripts/gen-lang-template.mjs` for `template.json`; see `Update/Documentation/TranslationGuide_EN.md`. |
| Add a doc page | `BMM Docs/docs/<section>/<page>.md` + `.fr.md`, nav in `BMM Docs/mkdocs.yml`, then `node scripts/sync-docs.mjs`. |
| Add a CI gate | `scripts/check-<name>.mjs`, append it to `ci` in `package.json` (see [CONTRIBUTING.md](CONTRIBUTING.md)). |
| Add a scheduler action | `ACTION_TYPES` in `frontend/src/features/settings/scheduler.ts`, then `npm run gen`. |

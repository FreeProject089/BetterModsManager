# Catalogs & Browsers — How BMM discovers content

BMM has four "browse" surfaces that all work the same way under the hood: a small
JSON index hosted somewhere public, fetched at runtime, with **multiple sources**
merged into one list. This guide explains each one and, crucially, **how to add
your own / several sources**.

> All source URLs live in **`frontend/assets/links.json`** (and the hosted copy on
> GitHub). BMM loads links remotely first, then the bundled copy, then built-in
> defaults — so you can change where catalogs come from without rebuilding the app.

---

## 1. Server Repo Browser

**What it is:** a directory of public mod repositories you can sync from.

**How it works**
- BMM fetches `server_browse` (a `repos.json`) listing repositories: name, URL, owner, description.
- Each entry points at a repository manifest (generated by BMM's *Generate Repo* / server tools).
- Selecting one lets you browse its mods and sync them into a profile.

**Adding repositories**
- The browse list itself is one JSON file (`repos.json`). To list several repos,
  add multiple objects to its array:
  ```json
  [
    { "name": "DCS Core Mods", "url": "https://.../repoA/repo.json", "owner": "..." },
    { "name": "Community Skins", "url": "https://.../repoB/repo.json", "owner": "..." }
  ]
  ```
- To point BMM at a *different* browse index, change `server_browse` in `links.json`.
- You can also paste a single repository URL directly in the repo view without using the browse index.

---

## 2. Plugin & API Catalog

**What it is:** the catalog of installable plugins shown in **Plugins & API → Catalog**.

**How it works**
- BMM fetches `plugin_catalog` (a `catalog.json`) listing plugins: id, name, version, description, download URL, permissions.
- Installing pulls the `.bmmplug` and registers it; permissions are shown before it can act.

**Adding plugins / sources**
- A catalog is a JSON array — add one object per plugin to list several:
  ```json
  {
    "plugins": [
      { "id": "auto-backup", "name": "Auto Backup", "version": "1.2.0", "url": "https://.../auto-backup.bmmplug" },
      { "id": "sync-bot",    "name": "Sync Bot",    "version": "0.4.1", "url": "https://.../sync-bot.bmmplug" }
    ]
  }
  ```
- Change `plugin_catalog` in `links.json` to host your own catalog.
- You can always import a local `.bmmplug` file directly (no catalog needed).

## 3. App Catalog

**What it is:** companion apps & tools, in the **App Catalog** sidebar page.

**How it works**
- BMM merges several sources: the official `apps_catalog`, partner catalogs, and any
  **community URLs** you add in the *Sources* tab.
- Each app entry: name, description, icon, category, price, download URL, optional checksum.
- Install downloads (and verifies, when a checksum is present) the app and tracks its version;
  installed cards offer Launch and Update.

**Adding multiple sources**
- Open **App Catalog → Sources**, paste a catalog URL, and it's merged into the list.
  Add as many community URLs as you like; remove any that fail to load.
- A source file lists multiple apps in one array:
  ```json
  {
    "apps": [
      { "name": "Tool A", "url": "https://.../toolA.zip", "category": "utility", "sha256": "..." },
      { "name": "Tool B", "url": "https://.../toolB.msi", "category": "audio" }
    ]
  }
  ```
- See `Update/Guides/Catalogs-and-Repos/app-catalog-format_EN.md` for the full schema.

> ⚠️ Only add sources you trust — installing an app runs its installer/executable.

---

## 4. Theme Catalog

**What it is:** shareable UI themes, in the **Theme Editor → Installed / catalog**.

**How it works**
- Themes are JSON of `--bmm-*` tokens + element overrides + assets, packaged as `.bmmtheme` (a ZIP).
- The catalog lists themes from official, partner and community sources.
- Installing applies the theme instantly (no restart); everything is reversible.

**Adding / sharing themes**
- **Export** a theme as a `.bmmtheme` file, or use **Share** to copy a one-click
  `bmm://theme/import-inline?data=…` link.
- To list several themes in a catalog, use a JSON array of theme entries (id, name, author, download URL).

---

## Common pattern (summary)

| Browser | links.json key | Index file | Add more by… |
|---|---|---|---|
| Server Repo | `server_browse` | `repos.json` | adding objects to the array / pasting a repo URL |
| Plugins & API | `plugin_catalog` | `catalog.json` | adding plugin objects / importing `.bmmplug` |
| App Catalog | `apps_catalog` + community URLs | `catalog.json` | Sources tab → add URL |
| Themes | (theme catalog) | theme list | export/share `.bmmtheme` / inline link |

The takeaway: **every catalog is just a hosted JSON list, and "adding several" means
adding more entries to that JSON or registering more source URLs.** Change the URLs in
`links.json` to host any of them yourself.

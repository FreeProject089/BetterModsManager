# Better Mod Manager: everything new since 0.9.11

Every new feature, improvement and notable fix from 0.9.11 to 1.0.4, sorted by area, one line per change.

- **0.9.12** was only a bridge: its updater installs only what a signed update manifest lists, so 0.9.11 can reach 1.0 safely.
- **1.0.0 to 1.0.2** is the 1.0 release (1.0.1 was a pre-release; its changes ship in 1.0.2).
- **1.0.4** is the latest release.

The tag at the end of each line is the version that brought it: (0.9.12) the update bridge, (1.0.0) the 1.0 release, (1.0.2) the first stable update after it, (1.0.4) the latest.

**Download 1.0.4:** https://github.com/FreeProject089/BetterModsManager/releases/tag/v1.0.4

## Library and mods

- **Integrity scan (SHA-256)**: a deep scan of each mod folder, based on SHA-256 fingerprints, finds missing, modified or unknown files (1.0.0)
- **Red shield**: a pulsing red shield marks a damaged mod, and the icons update at once in the library and the details panel after a scan (1.0.0)
- **Integrity remembered**: the integrity state is saved with the mod, so problems show as soon as BMM starts (1.0.0)
- **No broken mods enabled**: a mod with missing or corrupted files cannot be enabled (1.0.0)
- **ContentID**: every mod gets a fingerprint of its files: the same files on any PC give the same ID, whatever the folder name (1.0.0)
- **Matching by content**: `.mm` lists, modpacks and repo syncs match mods by content, and an import says which mods you already have (1.0.0)
- **Updates history**: a log of every change to a mod's name, version, author, description, tags, links and dependencies, with exact timestamps and a badge for each field changed (1.0.0)
- **History filter**: filter the updates history by type of change (1.0.0)
- **History retention**: choose how long the history is kept (for example 30 days or 6 months), or clear it in one click (1.0.0)
- **Modernised filter bar**: a redesigned filter bar with clearer hover and active states (1.0.0)
- **Search box**: a sharper focus state on the library search box (1.0.0)
- **View toggle and profile selector**: the compact or grid toggle and the profile selectors match the new bar (1.0.0)
- **Tag icons**: a tag can carry an icon from the shared library (1.0.0)
- **Tag gradients**: a tag can use a two-colour gradient instead of a flat colour (1.0.0)
- **Editable tags**: tags can be edited, with an explicit Cancel, instead of only created (1.0.0)
- **One look per tag**: a tag looks the same in the card grid, the list, the details panel, the « +N » window and Settings (1.0.0)
- **Shared icon library**: 2017 Lucide icons and 3453 brand icons (Simple Icons) in one picker with search and tabs (1.0.0)
- **Your own icons**: upload your own image (PNG, JPG, SVG, WebP, up to 128 KB) as an icon (1.0.0)
- **Icons everywhere**: the icon picker serves tags, the profile icon and plugin creation, and icons travel with exported profiles, repos and catalogues (1.0.0)
- **Icons load on demand**: showing a saved brand icon loads about 150 KB instead of the full 4.6 MB pack (1.0.0)
- **Isometric icons**: a set of isometric icons in the icon picker (1.0.0)
- **Where a mod came from**: the details panel says whether a mod was added by hand, from a link, from a server repo or from someone's mod list, read from the fields the updater uses (1.0.0)
- **Repo without checksums**: a mod from a repo that shipped no checksums says so (1.0.0)
- **Updates section**: « Check for updates » and « Configure updates » left the card menu for a section of the details panel, which lists what updates the mod (1.0.0)
- **Protected links**: a link in a mod's details can reach a host that asks for a password or an identity key (1.0.0)
- **New link kinds**: mod links can be of kind repo and http(s) (1.0.0)
- **Compact view, details too**: in compact view the details panel gets tighter fields and a shorter box; everything still scrolls (1.0.0)
- **Destination folder**: « Game directory » is now « destination folder » everywhere: app, docs, tutorials and error messages (1.0.0)
- **Docked panel space**: the library action bar makes room for a docked panel (1.0.0)
- **Safer activation**: file operations during activation are all-or-nothing, with consistent conflict handling (1.0.0)
- **Selection stays open**: Enable and Disable no longer close selection mode after starting the job (1.0.2)
- **Clearer selection icons**: enable (check), disable (close), select all (list), select none (clear) (1.0.2)
- **Tag filter dots**: the tag filter shows a colour dot only when the tag has no icon (1.0.2)
- **Shorter label**: the « Multi-profile » label is shorter (1.0.2)
- **Mod details window**: mod details open in a centred window with tabs: Overview, Details, Files, Conflicts & order, Updates & links (1.0.4)
- **Next and previous mod**: the Up and Down arrows or the ‹ › buttons move to the next or previous mod, and Escape closes the window (1.0.4)
- **Unsaved changes**: unsaved changes in mod details ask before they are discarded (1.0.4)
- **Protected game folder warning**: the Library header warns when the profile's game folder is in a folder Windows protects (1.0.4)

## Conflicts and activation order

- **Activation order**: when two mods ship the same file, the last one in the order wins (1.0.0)
- **Order in mod details**: the details panel shows what a mod overwrites and what overwrites it (1.0.0)
- **Order from the menu and keyboard**: move a mod in the order from the right-click menu or with Alt+arrows (1.0.0)
- **Order view**: a full view of the order with drag, sorts and live hints (1.0.0)
- **Only what changes hands**: moving a mod re-copies only the files that change owner (1.0.0)
- **Re-apply**: « Re-apply » repairs the game folder from the current order (1.0.0)
- **Share an order**: as a code, a `bmm://order` link, a readable list or a file (1.0.0)
- **Import an order**: import shows a preview first and never enables or disables a mod (1.0.0)
- **Order travels**: the order is kept in `.mm` lists, modpacks, exports and backups (1.0.0)
- **Top mod fix**: disabling the top mod could restore the oldest copy of a file; fixed (1.0.0)
- **Batch disable fix**: a batch disable could delete a game original; fixed (1.0.0)
- **Conflicts legend**: the conflicts panel explains Intra (same profile), Inter (another profile on the same game folder), Active (on disk now) and Potential (the other mod is disabled) (1.0.0)
- **State filter**: the conflict filters gain a state filter: happening now, or only if something changes (1.0.0)
- **Clear empty list**: an empty conflict list tells « no conflicts » apart from « your filters hid them all » (1.0.0)
- **Conflicts view**: for every file two active mods share, it says whose copy is on disk with the current activation order (1.0.4)
- **Summary per pair**: the Conflicts view sums up each pair of conflicting mods (1.0.4)
- **Make X win**: resolve a conflict by moving a mod up or down, or with « Make X win » (1.0.4)
- **Keep one mod's copy**: keep one mod's copy of chosen files whatever the order, remembered per profile (1.0.4)
- **Disable from the view**: resolve a conflict by disabling a mod from the Conflicts view (1.0.4)
- **Decide for many files**: tick several files to decide for all of them at once (1.0.4)
- **Nothing before Apply**: nothing changes until Apply, and BMM first says how many files it would re-copy (1.0.4)
- **Show changes**: « Show changes » lists each file that would be re-copied (1.0.4)
- **Apply in the background**: applying runs in the activity centre and re-copies only those files (1.0.4)
- **Open it from anywhere**: from a mod's conflict badge in the library, from the mod details, or from the command palette (« Resolve conflicts ») (1.0.4)

## Modpacks, .mm lists and backups

- **Tags survive a .mm**: tags arrive with their names and icons instead of raw ids (1.0.0)
- **Install notes travel**: a `.mm` carries each mod's install notes, which used to arrive empty (1.0.0)
- **Provenance travels**: a `.mm` carries where each mod came from and how it updates (source repo, repo id, update address, id and fingerprint), so shared mods keep updating (1.0.0)
- **Old lists still open**: every `.mm` ever written still opens; the new fields are optional (1.0.0)
- **Locked mod lists**: a passphrase seals a `.mm` with Argon2id and AES-256-GCM, and a tampered file fails to open (1.0.0)
- **Readable header**: a locked list keeps its name, author, game and mod count readable, so it can still be checked before trusting it (1.0.0)
- **Signed, then locked**: the list is signed before it is locked, so the signature says who made it (1.0.0)
- **No recovery**: no reset, no hint: lose the phrase and the file cannot be opened (1.0.0)
- **Credentials in a shared list**: optional and off by default: download passwords and identity keys, separately, only for the hosts the list points at, sealed with a passphrase (1.0.0)
- **Only passwords typed this session**: download passwords live in memory only, so a list can carry only those typed since launch (1.0.0)
- **Importing asks twice**: passwords are offered for the session; keys get their own question and a warning, and a key name already on your ring is skipped, never overwritten (1.0.0)
- **.mm export cancel**: the Cancel button of the export progress really stops the export and shows « Export cancelled » (1.0.0)
- **No half-written file**: a cancelled export leaves no incomplete `.mm` behind (1.0.0)
- **.mm install cancel**: Cancel also stops a running `.mm` install (1.0.0)
- **Locked data backups**: a `.DATABMM` backup with a passphrase is encrypted as a whole: opened in a zip tool, it is not a zip at all (1.0.0)
- **Identity keys in backups**: identity keys can ride along in a backup, and BMM refuses to write them without a passphrase (1.0.0)
- **Modpack cards**: modpack cards no longer flicker at their edge on hover (1.0.0)
- **Modpacks overview bar**: search, Active or Inactive, sort, and grid or list (1.0.4)
- **One action per card**: each modpack card has one main action and a « … » menu (1.0.4)
- **Create in four steps**: Basics, Mods, Options, Review (1.0.4)
- **Import a modpack**: from a file, a link or a catalogue (1.0.4)
- **Pack IDs**: « Export & share » shows the pack IDs (1.0.4)

- **Verified servers only**: the repo browser lists only servers validated by the BMM team (1.0.0)
- **Verified badge**: each listed server carries a green Verified badge (1.0.0)

- **GitHub browse**: discover server repos hosted on GitHub from the browser (1.0.0)
- **.zip support**: the Server Repo flow accepts `.zip` (1.0.0)
- **Linux server**: the lightweight standalone server runs on Linux (1.0.0)
- **Repo history**: BMM keeps a history of the repos you used (1.0.0)
- **Download password**: a self-hosted repo can require a download password, set when you generate the server; blank means an open repo (1.0.0)
- **Asked once**: subscribers type the password once, with retry, and BMM remembers it for later syncs (1.0.0)
- **Not the admin password**: the download password is separate from the admin password, which only guards the host's admin panel (1.0.0)
- **Password everywhere**: the password works in the mini-server and export forms, the API, the plugins Quick Test and the `bmm://repo/sync` link (1.0.0)
- **bmm://repo/sync fixed**: the link now fills the sync form (address, folders, profile, password) instead of only opening the page (1.0.0)
- **Close a generated server**: every generated server (Multi-Repo Hub, Express standalone, lightweight v1 and v2 in `.bat` and `.sh`) reads an `access.json`: a password, authorised public keys, or both (1.0.0)
- **Read at each request**: authorising a subscriber means editing one small file: no regenerating, no re-uploading (1.0.0)
- **Per repo folder**: in the Multi-Repo Hub, each repo folder has its own `access.json`, so an open repo can sit beside a locked one (1.0.0)
- **Audience field**: `audience` is the address your subscribers type, so a key proof captured elsewhere cannot be replayed on your server (1.0.0)
- **You keep access**: the gate runs after bans and the whitelist, before anything is sent, and your dashboard and admin routes stay reachable (1.0.0)
- **Static export README**: a static hub export ships a README saying it cannot enforce any of this (1.0.0)
- **Update over SFTP**: « Update from the server » reads over SFTP as well as HTTP, for a repo that only exists on an SSH machine (1.0.0)
- **SSH credentials block**: both update screens pick a configured SSH server and ask for the account password and key passphrase, which BMM never stores (1.0.0)
- **Password-based SSH**: servers that sign in with a password now work from the update dialog (1.0.0)
- **Publish over SSH with your keys**: publishing over SSH can take its private key from your identity keys, picked by name (1.0.0)
- **Why a write was refused**: the connection test shows the remote folder's owner and mode, the account BMM used and the `chown` line that fixes it (1.0.0)
- **SSH servers dialog**: SSH servers have their own dialog, opened from every panel that publishes, instead of a form inside « Generate Repository » (1.0.0)
- **One publish and fetch panel**: the same panel in the export folder, the repo being updated, the manifest card (sends the `repo.json` file) and the catalogue builders (1.0.0)
- **Per-transfer destination**: the destination starts at the server's base folder and a change applies to this transfer only (1.0.0)
- **Passphrase never stored**: the key passphrase is read at the moment of use and stored nowhere (1.0.0)
- **Remote folder browser**: a real browser with a clickable path, folders and files with their sizes, in a fixed-height pane above the dialog that opened it (1.0.0)
- **Browse the base folder**: the SSH servers dialog has the same browser on its base folder field (1.0.0)
- **« Update Server Repo » untangled**: two labelled blocks (this disk, a server) instead of four controls side by side (1.0.0)
- **Duplicate button removed**: the extra « From the server » button is gone; the shared panel does the same transfer and shows its destination (1.0.0)
- **Credentials in a repository**: a repo can carry sealed download passwords and identity keys for the protected sources its mods point at, sealed before the manifest is signed (1.0.0)
- **Kept on re-export**: the sealed credentials are carried forward on re-export like extras and modpacks; asking for none clears them (1.0.0)
- **Zip compression choice**: a repo export picks its compression: deflate, zstd, bzip2 or stored (1.0.0)
- **Simple by default**: the page opens on the guided steps to sync or host a repo (1.0.2)
- **Advanced tools**: everything else sits in a searchable « Advanced tools » area that remembers which tools you opened (1.0.2)
- **Create a repo in one click**: from a profile, a modpack or a folder of mods (1.0.2)
- **Validate a repo**: manifest, files, hashes, signature and format version in one report, in one pass with progress and Cancel, re-reading only files that changed (1.0.2)
- **Set the repo version**: the number subscribers see beside the repo's name, re-signed (1.0.2)
- **Preview as subscribers see it**: the card BMM shows after Fetch, from the folder or the running server (1.0.2)
- **Share link**: a one-click link and a message to send, with password or key notes when needed (1.0.2)

- **One gate for bmm:// links**: a web page could make BMM run a program or install from a chosen address; every link action that changes something now asks inside BMM first (1.0.0)
- **Deeplinks need a permission**: firing a deeplink from a task now needs its own grant; it was not gated before (1.0.0)
- **Shared automations arrive disabled**: an imported `.bmmpa` or `.bmmscript` arrives off with all four permissions removed, and BMM says what it had asked for (1.0.0)
- **Resources consent**: a `.bmmscript` granting itself resources shows the consent box (1.0.0)
- **One passphrase envelope**: backups, mod lists and identity keys share Argon2id and AES-256-GCM; the cost settings travel with the file (1.0.0)
- **Files stay in their folder**: a crafted `repo.json`, `.mm` or `.7z` could write outside its folder; refused before any write (1.0.0)
- **Mini-servers confined**: generated mini-servers stay inside their folder and no longer serve their own config (1.0.0)
- **Blog comment link**: a link in a blog comment could run a command; fixed (1.0.0)
- **Sanitised READMEs**: a plugin's bundled README and other outside documentation are sanitised, and shown as plain text if that fails (1.0.0)
- **Read-only means read-only**: a read-only API permission could write a file anywhere; fixed (1.0.0)
- **Token guessing**: a web page could tell a right API token from a wrong one; fixed (1.0.0)
- **No secrets in reports**: crash and report zips no longer carry your tokens or your BetterCommunity key (1.0.0)
- **Signed Quick Update**: the incremental update manifest is signed and expires after 7 days (1.0.0)
- **Creator key v5**: your Creator ID stays the same; the key that proves it is separate, encrypted and pinned (1.0.0)
- **AI keys scoped**: an AI key only goes to the address it was saved for (1.0.0)
- **AI output checked**: generated text with unsourced links, paths or commands is dropped, and text from mods is data, never instructions (1.0.0)
- **Constant-time passwords**: generated mini-servers and hub servers compare the download and admin passwords in constant time (1.0.0)
- **Dependency advisories**: rmcp updated (an advisory that could not reach BMM's stdio-only MCP server) and the dompurify advisory fixed (1.0.0)
- **Trust an SSH server**: a server seen for the first time shows its key fingerprint and asks « Trust this server » before anything is sent to it (1.0.4)
- **Changed SSH key refused**: a changed key is refused, with both fingerprints side by side (1.0.4)
- **Theme colours confined**: a colour value that tries to break out of the stylesheet is ignored (1.0.4)
- **Theme archive ids**: an imported theme archive whose id is not a plain name is refused, since it could write outside the themes folder (1.0.4)
- **Plugin duplicate confined**: duplicating a plugin copies only files inside its folder; absolute paths, `..` and links are left out (1.0.4)
- **Secrets protected by Windows**: repo download passwords and the future BetterCommunity v2 sign-in are kept like BMM's other secrets, protected by Windows for your account, and only sent to their own address (1.0.4)
- **Narrow proxy bypass**: skipping the system proxy applies only to repo addresses on your PC or network; the blocks on local addresses for tasks, AI endpoints and custom pages are unchanged (1.0.4)

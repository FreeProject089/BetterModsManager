C'est quoi Better Mods Manager ?

Better Mods Manager (BMM) est un gestionnaire de mods local pour les jeux PC. Il te permet d'activer ou désactiver des mods en quelques clics, de gérer plusieurs configurations via des profils, et d'automatiser tes setups avec des plugins et scripts. Aucun fichier n'est modifié dans le dossier du jeu : BMM utilise des liens symboliques pour "brancher" ou "débrancher" tes mods à la volée, sans jamais copier ni supprimer de fichiers.

Profils

Plusieurs configs par jeu. Passe de "Serveur PvP" à "Solo" en un clic.

Activation par copie

Activer un mod copie ses fichiers dans le dossier du jeu. Les originaux sont sauvegardés et restaurés à la désactivation.

Plugins & Scripts

Partage ta liste de mods via un fichier .bmmplug ou automatise tout avec l'API locale.

Modpacks & Dépôts

Regroupe des mods en modpacks, synchronise depuis un dépôt de serveur distant.

Comment BMM fonctionne

Chaque profil dans BMM repose sur 3 chemins que tu configures une seule fois :

Dossier du jeu

Là où le jeu est installé. BMM y copie les fichiers des mods actifs.

Dossier des mods

Le dossier où tu stockes tous tes mods. BMM le scanne pour construire ta liste.

Dossier de backup

BMM sauvegarde ici les fichiers originaux du jeu avant de les remplacer.

Ce qui se passe quand tu actives un mod
  1. BMM scanne le dossier du mod et liste tous ses fichiers.
  2. Pour chaque fichier, si un original du jeu existe au même chemin et n'a pas encore été sauvegardé, BMM le copie dans le dossier de backup.
  3. BMM copie ensuite le fichier du mod dans le dossier du jeu, au chemin exact correspondant.
  4. Le mod est actif — le jeu voit les fichiers du mod à leur place normale.
Ce qui se passe quand tu désactives un mod
  1. BMM supprime les fichiers copiés dans le dossier du jeu.
  2. Si un backup existait, il est restauré — le jeu retrouve ses fichiers originaux.
  3. Si plusieurs mods étaient actifs sur le même fichier (stacking), BMM remet le fichier du mod précédent.
La règle d'arborescence

Chaque fichier du mod doit avoir le même sous-chemin relatif que sa cible dans le jeu. BMM s'en sert pour savoir exactement où copier. Le mod n'a besoin de contenir que les fichiers qu'il modifie.

Exemple générique — les chemins réels dépendent de ton jeu
Dossier du jeu (tous les fichiers du jeu) 
MonJeu/                ← game_path
├── game.exe
├── Data/
│   └── Skins/
│       ├── hero_skin.png  ← original
│       └── map.png         ← original
└── Config/
    └── settings.cfg   ← non touché
Dossier du mod dans BMM (seulement les fichiers modifiés) 
MonMod-HD-Skins/       ← dans mods_path
└── Data/
    └── Skins/
        ├── hero_skin.png  ← remplace
        └── map.png         ← remplace

  ↑ Pas de game.exe, pas de Config/
    Le mod ne touche QUE les textures.

BMM prend Data/Skins/hero_skin.png dans le mod et le copie au même chemin dans game_path. Les fichiers non présents dans le mod (game.exe, Config/…) ne sont jamais touchés.

En pratique : la plupart des mods sont distribués déjà dans le bon format. Tu places le dossier du mod dans ton dossier de mods BMM, BMM le détecte automatiquement. N'efface jamais manuellement des fichiers dans le dossier du jeu sans passer par BMM — utilise toujours les boutons Activer / Désactiver.

Modpacks & Sharing

Les Modpacks sont des collections de mods empaquetées dans un fichier .bmp. Ils utilisent des empreintes numériques (SHA-256) pour identifier vos fichiers, ce qui permet à vos amis de retrouver exactement les mêmes versions, même s'ils ont installé leurs mods différemment.
Empreintes SHA-256
Identification unique des fichiers pour une compatibilité garantie entre joueurs, même avec des noms de dossiers différents.
Multi-Profile Support
Créez des packs contenant des mods venant de plusieurs profils BMM différents en une seule activation.
Portabilité Totale
Exportez votre configuration en un clic. Vos amis n'ont qu'à importer le fichier pour synchroniser leur jeu.

Comment créer un pack ?

  1. Allez dans l'onglet Modpacks et cliquez sur Créer.
  2. Donnez un nom et une description à votre pack.
  3. Ajoutez les mods souhaités. BMM récupérera automatiquement leurs signatures SHA-256.
  4. (Optionnel) Ajoutez des liens de téléchargement directs pour faciliter la vie de vos amis.
  5. Sauvegardez et cliquez sur Exporter pour obtenir votre fichier .bmp.

Server Repository

The Server Repository lets you host your mod collection on a local or remote server so that your team can download and sync mods in one click — no manual file sharing needed.

Creator ID

Empreinte matérielle unique générée depuis les composants de ta machine. Elle t'identifie d'une session à l'autre sans login — le serveur l'utilise pour tracker les téléchargements et l'admin pour gérer bans et whitelists par utilisateur (et non par IP).

Server Seed

Secret persistant qui définit l'identité du serveur. Bans, whitelists et règles d'accès sont liés à ce seed — redémarrer le serveur ne remet rien à zéro. Laisse vide à l'export pour en générer un automatiquement ; réutilise-le si tu reconstruis le serveur.

Multi-Serveurs

Les clients peuvent se connecter à plusieurs serveurs simultanément. Chaque serveur a sa propre URL. La vue JOIN affiche tous les serveurs ajoutés — idéal pour un escadron dont les mods sont répartis sur plusieurs hosts.

Comment ça fonctionne
1 Dans l'onglet Server Repo → HOST, configure ta collection de mods, ton server seed (ou laisse vide pour auto-générer), puis clique sur Générer. BMM crée le repo.json avec les métadonnées et hashes de tous tes mods.
2 Clique sur Démarrer le serveur — le Mini Serveur intégré à BMM démarre et sert tes mods directement depuis ta machine sur une URL locale (ex : 192.168.x.x:7272). Pour un accès public, active Cloudflare Tunnel ou ngrok depuis les options du serveur.
3 Partage l'URL du serveur à ton équipe. Chaque membre va dans Server Repo → JOIN, colle l'URL et voit instantanément la liste de tous les mods disponibles avec leur statut (à jour, manquant, version différente).
4 Le client clique Sync — BMM compare les hashes locaux aux hashes du repo.json du serveur. Seuls les fichiers manquants ou différents sont téléchargés, avec le Creator ID envoyé en header pour identifier le client auprès de l'admin.
Admin note: The Creator ID shown in the monitoring dashboard comes from the client's BMM. It's a hardware fingerprint — not a password. Use it to whitelist trusted users or ban abusers across sessions, even if their IP changes.

BENCHMARK & PERFORMANCES

Le bouton Benchmark (icône d'activité) ouvre un panneau à deux onglets : Live Monitor (CPU / RAM / disque en temps réel pendant que vous utilisez BMM) et Benchmark (mesure la vitesse réelle des opérations de BMM sur un jeu de données contrôlé).

Deux modes de données

Sandbox (par défaut, sûr) : BMM génère de faux mods dans un dossier temporaire — rien de personnel n'est touché. Mes mods : un sélecteur de profils apparaît — choisissez un profil, plusieurs, tous, ou un dossier personnalisé ; BMM utilise une copie de ces vrais fichiers comme données de test. Dans les deux cas, toutes les écritures se font dans un espace temporaire supprimé à la fin — votre dossier de jeu n'est jamais modifié.

Taille du jeu de données

La taille correspond au volume total de fichiers de mods utilisés pour le test — c'est ce qui détermine la quantité de données réellement lue, copiée et hachée. Plus elle est grande, plus le résultat reflète une grosse bibliothèque (et plus le test dure) :

  • S ≈ 6 Mo — test rapide, petite collection.
  • M ≈ 48 Mo — défaut équilibré.
  • L ≈ 160 Mo — grosse collection.
  • XL ≈ 400 Mo — très grosse bibliothèque.
  • Custom — saisissez une cible exacte en Mo (1–4096) ; BMM génère assez de faux fichiers (~256 Ko chacun) pour atteindre ce total.

En mode « Mes mods », la taille réelle est celle des profils/dossiers que vous sélectionnez (plafonnée pour rester raisonnable), pas le préréglage.

Ce qui est mesuré

Les vraies opérations de BMM, chacune échantillonnée plusieurs fois (médiane + plage min/max) :

  • Analyse des fichiers du mod
  • Hachage de contenu (BLAKE3)
  • Copie — pleine vitesse
  • Copie — Smart I/O
  • Extraction des mods archivés
  • Activation d'un mod (décompressé)
  • Activation d'un mod archivé (.zip)
  • Désactivation d'un mod
  • Annulation d'une opération
  • Vérification d'intégrité (BLAKE3)

Lire les résultats

Chaque opération affiche sa médiane et la plage min–max, son débit (Mo/s) le cas échéant, et une explication. Deux graphiques SVG en haut résument le temps et le débit. Copier JSON copie le résultat complet ; Exporter le rapport enregistre un rapport HTML autonome (graphiques + tableau).

Lecture seule : le benchmark ne modifie jamais vos mods ni votre jeu. Toutes les opérations s'exécutent dans un espace de travail temporaire.

Pour les développeurs, une suite plus poussée (Criterion, hyperfine, micro-benchmarks JS) vit dans le dossier benchmarks/ du dépôt.

FAQ

Le benchmark peut-il abîmer mes mods ou ma sauvegarde ?

Non. Même en mode « Mes mods », BMM travaille sur une copie dans un espace temporaire supprimé à la fin. Votre dossier de jeu et vos mods d'origine ne sont jamais modifiés.

Que signifie la taille du dataset (S / M / L / XL) ?

C'est le volume total de faux fichiers de mods générés pour le test (≈ S 6 Mo, M 48 Mo, L 160 Mo, XL 400 Mo). Plus c'est grand, plus le test reflète une grosse bibliothèque — et plus il dure.

Pourquoi mes résultats diffèrent-ils d'une fois à l'autre ?

La vitesse dépend de votre disque (SSD/HDD), du cache du système et de la charge en cours. Chaque opération est échantillonnée plusieurs fois et BMM affiche la médiane + la plage min–max pour lisser ces variations.

Fichiers Générés — Déployer votre Serveur

Quand vous générez un repo dans le Serveur Autonome (Léger), BMM crée automatiquement ces 2 fichiers dans le dossier de sortie. Copiez ce dossier sur votre machine hôte (Linux ou Windows) et lancez le script pour démarrer le serveur.
repo.json — Manifeste du dépôt
{
  "name": "Mon Serveur de Mods",
  "version": "2",
  "creator_id": "a1b2c3d4e5f6",
  "seed": "xyz789abc",
  "port": 8080,
  "upload_limit_kb": 0,
  "password_hash": "$argon2id$v=19$...",
  "whitelist": [],
  "banned": [],
  "mods": [
    {
      "name": "ExampleMod",
      "version": "1.0.0",
      "file": "mods/ExampleMod-1.0.0.zip",
      "sha256": "abc123def456...",
      "size": 1048576,
      "required": true
    }
  ]
}
Le champ creator_id est lié à votre machine (hardware-derived) et généré automatiquement. Le seed identifie ce repo de façon unique.
start_server.bat Windows
@echo off
:: BMM Standalone Server — Windows
set PORT=8080
set ADMIN_PASSWORD=admin
set REPO_PATH=%~dp0repo.json
BMM-Standalone-Server.exe
  --port %PORT%
  --repo "%REPO_PATH%"
  --password "%ADMIN_PASSWORD%"
pause
start_server.sh Linux / Docker
#!/bin/bash
# BMM Standalone Server — Linux
PORT=8080
ADMIN_PASSWORD="admin"
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
chmod +x "$SCRIPT_DIR/BMM-Standalone-Server"
"$SCRIPT_DIR/BMM-Standalone-Server" \
  --port $PORT \
  --repo "$SCRIPT_DIR/repo.json" \
  --password "$ADMIN_PASSWORD"

FAQ & Help

Réponses aux questions les plus fréquentes sur Better Mod Manager.

Général
Est-ce que mes mods sont conservés si je change de profil ?
Oui ! Chaque profil garde son propre état de mods. Quand vous revenez sur un profil, vos mods activés sont toujours là, même après redémarrage.
Quelle est la différence entre .MM et .JSON ?
Aucune techniquement ! .MM est simplement un fichier .JSON renommé pour faciliter le partage entre joueurs.
Comment obtenir un token GitHub PAT ?

Un Personal Access Token (PAT) vous permet de télécharger plus de 60 mods/heure depuis GitHub. Voici comment en créer un :

  1. Connectez-vous à github.com avec votre compte.
  2. Cliquez sur votre avatar en haut à droite → Settings.
  3. Dans le menu de gauche, descendez jusqu'à Developer settings (tout en bas).
  4. Cliquez sur Personal access tokens → Tokens (classic).
  5. Cliquez sur Generate new token (classic).
  6. Donnez-lui un nom (ex: BMM Downloads), choisissez une durée d'expiration, et cochez uniquement public_repo dans la section repo.
  7. Cliquez Generate token, copiez le token (il commence par ghp_) et collez-le dans le champ GitHub PAT des paramètres de BMM.
⚠️ Ne partagez jamais votre token ! Il donne accès à votre compte GitHub.
À quoi sert le limiteur d'E/S disque ?

Le limiteur d'E/S (entrées/sorties) permet de réduire l'impact de BMM sur les performances générales de votre PC pendant les opérations de copie ou de téléchargement, en limitant la vitesse à laquelle les données sont lues ou écrites sur le disque.

Comment voir la taille de mes mods par profil ?
La taille occupée par le dossier de mods de chaque profil est affichée directement sur la carte du profil (icône disque, en bas à droite de la ligne de compteur de mods). L'information se charge en arrière-plan quelques secondes après l'ouverture de l'onglet Profils.
Pourquoi l'export ZIP est-il long ?
BMM effectue deux tâches lourdes : d'abord, il calcule une empreinte numérique unique (SHA-256) pour chaque fichier afin de garantir une synchronisation parfaite. Ensuite, il compresse le tout. Pour 20 Go+, c'est une opération massive pour le CPU et le Disque.
Puis-je héberger sur mon propre serveur ?

Oui ! BMM est conçu pour le self-hosting. Vous pouvez utiliser n'importe quel VPS Linux (Ubuntu recommandé). Référez-vous au guide de déploiement dédié dans l'onglet 'Avancé'.

Comment créer un lien d'installation en 1-clic valide ?

Technique
Comment fonctionnent les Modpacks (SHA-256) ?

Les modpacks de BMM utilisent des empreintes numériques (SHA-256) pour identifier vos mods de manière unique.

Comment fonctionne la reprise de téléchargement ?

BMM découpe les fichiers volumineux en morceaux de 4 Mo. Si une erreur survient (coupure internet, crash ou fermeture), BMM vérifie quels morceaux sont déjà validés et ne télécharge que les parties manquantes.

C'est quoi Docker et pourquoi BMM l'utilise ?

Docker est un système de conteneurisation : il emballe le serveur BMM et toutes ses dépendances dans une boîte isolée. Résultat — une seule commande pour démarrer le serveur, peu importe l'OS (Windows, Linux, macOS), sans rien installer manuellement.

Comment mettre a jour le serveur Docker ?

Mettre a jour le serveur BMM avec Docker se fait en 3 commandes. Vos donnees (mods, bans, config) sont conservees dans le volume ./data et ne sont pas affectees.

# 1. Telecharger la nouvelle image
docker compose pull
# 2. Redemarrer avec la nouvelle version
docker compose up -d
# 3. Nettoyer les anciennes images (optionnel)
docker image prune -f
Vos données dans ./data ne sont jamais effacées lors d'une mise à jour.
Application Updates
Comment fonctionne la mise a jour incrementale de BMM ?

BMM propose deux modes de mise a jour. Si la release GitHub contient un update-manifest.json, BMM utilise le mode delta : seuls les fichiers modifies sont telecharges, chacun vrifie par SHA-256 et remplace atomiquement. Sinon, BMM propose le telechargement de l'installeur complet (.msi/.exe).

Mode Delta (prioritaire)
+ Telechargement minimal
+ SHA-256 par fichier
+ Remplacement atomique
+ Progression en temps reel
Installeur complet (fallback)
~ Telechargement complet
+ Toujours disponible
+ Verification SHA-256
+ Lance l'installeur
Critique & Avertissements
Que se passe-t-il si je supprime un mod activé ?

Vous devez d'abord désactiver le mod pour que ses fichiers soient retirés du jeu et les backups restaurés, puis vous pouvez le supprimer en toute sécurité.

Que se passe-t-il si mon disque est plein ?

BMM vérifie l'espace avant chaque copie. Si le disque est plein, l'activation est bloquée.

Puis-je désactiver la limite de sécurité ?
Non, le blocage en cas de disque saturé est vital pour protéger vos données.

What is the Creator ID?
The Creator ID is a unique hardware fingerprint generated by BMM from your machine. It identifies your client to the server without requiring a login — the server admin can use it to whitelist or ban users persistently, even if their IP address changes.
What is the Server Seed?
The Server Seed is a secret string that defines your server's persistent identity. Ban lists and whitelist rules are tied to it — so restarting or redeploying the server keeps all your admin settings intact. Leave the field empty when exporting to auto-generate one, or paste a previous seed to reuse an existing identity.

Sécurité & Accès
Différence entre Accès Complet et Limité ?

L'Accès Complet permet à BMM de gérer vos fichiers sans restrictions (nécessaire pour le Storage Manager). L'Accès Limité restreint BMM aux seuls dossiers définis dans vos profils pour une sécurité maximale.

Who can use the local API, and is my token safe?
The API only listens on localhost, and any state-changing call requires your bearer token (read-only endpoints don't). Keep the token private — anyone with it can drive BMM. You can regenerate it any time from the Plugins & API page; that instantly invalidates the old one.
Is it safe to sync from someone else's repo?
Every file in a repo is verified by SHA-256 before install, and signed repos show a "Verified" badge if the content still matches what the author signed. Only sync from repo URLs you trust, and watch for a signature-mismatch warning — it means the content changed since it was verified.

Mod Updates & Repos
How does BMM know a mod has an update?
Each mod is linked to the repo it came from via a stable repo_mod_id. When you check for updates, BMM compares your installed version to the repo's current version and flags any that differ.
Can I update only some of the mods that have an update?
Yes. The updates modal groups available updates by repo and gives each mod a checkbox. Tick exactly the ones you want; the "Update N mod(s)" button updates only your selection via delta-sync (only changed files download).
Can BMM check for mod updates automatically?
Yes — set a "Mod update check interval" (minutes) in Settings. Leave it at 0 for manual-only. Mods with a detected update get an "Update" tag in your library.

Plugin & API System

Create, share and automate mod management via the BMM plugin system and local HTTP API.

Plugin Format (.bmmplug)

A .bmmplug file is a ZIP archive renamed with the .bmmplug extension. It contains a manifest and an optional icon.

The required_mods[].name must match the exact folder name of the mod as it appears in BMM's library (case-insensitive).

Archive structure

ZIP 
my-plugin.bmmplug
├── plugin.json     ← required — the manifest
└── icon.png        ← optional  (40×40 px recommended)

plugin.json — full structure

JSON 
{
  "id":          "my-server-pack",
  "name":        "My Server Modpack",
  "version":     "1.2.0",
  "author":      "YourName",
  "game":        "DCS World",
  "description": "Required mods for My Server",
  "official":    false,
  "permissions": ["mods.read", "mods.write"],
  "tags":        ["dcs", "multiplayer"],
  "website":     "https://myserver.example.com",
  "modlist": {
    "strict": false,
    "required_mods": [
      { "name": "ExactModFolderName", "optional": false },
      { "name": "OptionalMod",        "optional": true  }
    ]
  }
}

Strict vs Non-Strict mode

  • "strict": false — Only enables required mods. Does not touch other active mods.
  • "strict": true — Enables required mods AND disables all other active mods not in the list.
bmm:// Deep Links

Trigger BMM actions from any external script, bat file, or application by opening a bmm:// URL. No authentication needed.

Available URLs

  • bmm://mod/enable?id=mod-id  — Enable a specific mod
  • bmm://mod/disable?id=mod-id  — Disable a specific mod
  • bmm://profile/activate?id=prof-id  — Activate a profile
  • bmm://plugin/activate?id=my-server  — Apply plugin modlist
  • bmm://plugin/compare?id=my-server  — Compare modlist
  • bmm://modpack/enable?id=uuid  — Enable all mods in a modpack
  • bmm://modpack/disable?id=uuid  — Disable all mods in a modpack
  • bmm://modpack/create?name=X&profile=id  — Create a modpack from a profile
  • bmm://repo/connect?url=...  — Connect a server repo
  • bmm://repo/sync?url=...&profile=id  — Sync a server repo
  • bmm://repo/gen · bmm://repo/update?dir=... · bmm://repo/host?dir=...&port=8080
  • bmm://app/install?id=X&url=...&type=exe  — Install a catalog app
  • bmm://app/launch?id=X&exe=C:/path.exe  — Launch an installed app
  • bmm://mod/check-updates  — Check every linked mod for updates
  • bmm://mod/update?id=mod-id  — Update a specific mod (omit id = open updates)
  • bmm://theme/apply?id=theme-id  — Apply an installed theme
  • bmm://theme/import?path=theme.json  — Import a theme file
  • bmm://theme/editor  — Open the theme editor
  • bmm://language/import?path=fr.json  — Import a translation
  • bmm://restart  — Restart BMM
  • bmm://install?url=...&name=ModName  — One-click mod install
Generic passthrough — one deeplink for EVERY endpoint: bmm://api?method=POST&path=/api/mods/enable&mod_id=abc. Extra params become the JSON body (POST/PUT) or query string (GET/DELETE).

REM Enable a single mod

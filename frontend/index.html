Optional. When set, subscribers must enter this password to download from the repo.

Envoie le dossier exporté vers le serveur qui l’héberge, par SFTP. BMM lit votre clé privée au moment de l’envoi — elle n’est jamais copiée ni enregistrée.

  1. Générez le dépôt ci-dessus — c’est ce dossier qui part.
  2. Renseignez le serveur ici, puis testez.
  3. Publiez. Les envois suivants réutilisent ce qui est enregistré.

Ce qui est enregistré ici est ce que réutilisent l’action planifiée « Publier le dépôt par SSH » et POST /api/repo/publish-ssh — ils ne peuvent pas nommer d’hôte ni de clé eux-mêmes, exprès. Une clé protégée par une phrase secrète ne peut donc pas servir sans surveillance : rien de cette phrase n’est conservé, il n’y aurait personne à qui la demander.

Les clés OpenSSH et PuTTY (.ppk) sont acceptées telles quelles. La phrase secrète sert à cet envoi et n’est pas conservée.

Pour synchroniser DEPUIS ce dépôt, saisissez ssh:// comme URL dans la synchronisation : BMM utilisera la cible ci-dessus.

Le mot de passe sert à cette connexion et n’est jamais enregistré : il faut le retaper à chaque session. Certains serveurs refusent l’authentification par mot de passe — dans ce cas, utilisez une clé.

Vue Globale des Conflits

INTRA Un autre mod du même profil touche les mêmes fichiers. Les deux peuvent être activés ensemble — c'est le conflit qui compte tout de suite.
INTER Un mod d'un autre profil installé dans le même dossier de jeu. Ils ne peuvent pas être actifs en même temps : ça ne mord qu'au changement de profil.
ACTIF Les deux mods sont activés : le recouvrement existe sur le disque, maintenant. Le dernier activé (numéro #) gagne.
POTENTIEL Les fichiers se recouvrent mais l'autre mod est désactivé. Rien ne se passe tant que vous ne l'activez pas.
